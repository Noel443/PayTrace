# PayTrace：证据图谱与流式分析

## 开始前

1. 在项目根目录重新运行 `npm start`，访问 http://127.0.0.1:5173，刷新页面。
2. 在“服务配置 → 模型服务商”启用已配置的模型，点击“测试”确认可连接。支持 Chat Completions 兼容接口和本地 Ollama。
3. 测试和分析会发送实际模型请求；交易与日志为沙箱案例。未配置模型时，证据图谱、规则报告和补证仍可独立展示。

## 建议演示顺序（约 3 分钟）

### 1. 先看到异常在哪里

选择“外卡支付 → 支付成功，商户未收到通知”，点击“开始排查”。

报告顶部的“交易证据图谱”展示五个节点：交易受理、渠道响应、通知入队、通知处理、商户订单。通知处理显示异常，商户订单显示暂无证据。

点击“通知处理”，查看按消息 ID 关联的通知与重试记录，再点击证据查看日志原文。

讲解重点：平台支付成功与通知异常可以同时存在；没有通知确认，不能直接推断商户未处理。

### 2. 现场调用 AI

点击图谱右上角“AI 分析”，页面定位到分析区域，依次展示整理证据、连接模型和接收内容的实际进度。

模型逐步输出“已确认事实、可能原因、待核实事项、运营下一步”。有效的 `[E1]` 等引用可点击展开原文，对应图谱节点会短暂高亮。

讲解重点：这里是真实模型返回的分析摘要，每条判断应回到证据核实。图谱状态由关联记录和明确规则决定，不随模型措辞改变。

若模型服务返回完整 JSON，页面会说明“本次以整段分析显示”。没有伪造的打字动画或推理步骤。

### 3. 新证据改变结论

回到“下一步取证”，选择“商户订单已完成”，点击“补充证据并更新结论”。

观察商户节点从“暂无证据”变成“已有记录”，对照补证前后结论。通知异常仍保留，因为订单完成并不解释通知响应为什么没有确认。旧 AI 分析失效，可基于新证据重新分析。

### 4. 展示业务扩展

切换“MSO”，选择“境外收款人报备锁超时”。图谱展示收款人创建、报备任务、消息消费与任务锁等业务步骤，锁超时标为待核实。也可展示跨境支付的协议校验或银行上传案例。

三个空间共九个案例，业务文档和报告按空间隔离，模型连接共用。

## 调用失败时

- 点击“停止分析”会取消请求；尚未完成的文本明确显示未保存。
- 超时、响应截断或模型报错不会覆盖旧报告，也不会用预设文本代替真实输出。
- 切换页面、工作空间、重新生成报告或补入新证据，会取消旧分析。
- 完整分析保存到当前浏览器，导出的 Markdown 包含分析内容。

## 技术实现与边界

- 图谱：原生 SVG 连线与可访问按钮，无第三方依赖。按事件将当前报告的证据映射到业务节点；没有证据的步骤保持未知。
- 前端通过 `POST /api/ai/analyze/stream` 获取 SSE，事件类型为 `stage`、`delta`、`done`、`error`。
- 本地 Node 服务读取当前模型配置，调用上游流式接口，将 Chat Completions SSE 或 Ollama NDJSON 转为统一事件。
- 只显示模型公开回答字段，不读取或显示 `reasoning_content` 等内部推理字段。
- 上游请求上限 60 秒；用户停止或页面离开时取消连接。只有收到完整结束标记、输出有效、报告证据版本仍一致时才保存。
- 交易、日志与商户查单均未接入生产系统；预期业务链路和代码审阅摘要不代表现场执行或实时扫描。
