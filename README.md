## MySQL 配置、建表与旧数据迁移

简单说：先建数据库，依次执行 SQL，再填写连接信息并把 `driver` 改成 `mysql`，重启服务即可。没有启动 MySQL 时保持 `local`，演示可以照常运行；两种模式的数据彼此独立，切换不会自动搬数据。

配置文件是项目根目录的 **`config/database.json`**，模板为 [`config/database.example.json`](config/database.example.json)。实际配置不存在时使用本地存储；接入数据库时从模板复制，填写连接信息并生成自己的加密密钥。真实配置被 Git 忽略，不会提交。

```json
{
  "driver": "mysql",
  "host": "127.0.0.1",
  "port": 3306,
  "database": "paytrace",
  "user": "paytrace",
  "password": "你的MySQL账号密码",
  "connectionLimit": 5,
  "encryptionKey": "64位十六进制密钥"
}
```

`host` / `port` 是 MySQL 地址和端口，`database` 是库名，`user` / `password` 是数据库账号密码（与页面登录账号无关），`connectionLimit` 是连接数，取 2–20。`encryptionKey` 用于加密 SSH 密码及模型密钥，已生成私有导入 SQL 后不要更换它，否则无法解密。数据库备份需同时保管这份配置。全新安装可用以下命令生成密钥，仅将输出填入本机配置：

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
chmod 600 config/database.json
```

Node.js 的读取方式见 `scripts/database.mjs`：`readFile()` 读取 JSON，`JSON.parse()` 转成对象，再把 host、port、database、user、password 传给 mysql2 连接池。修改配置后重启生效；可用 `DATABASE_CONFIG_FILE=/路径/database.json npm start` 指定另一份配置。默认配置不存在时使用本地模式；文件损坏、显式指定文件不存在或 MySQL 不可连接时直接报错，不静默切换存储。

使用 **MySQL 8.0.16+ / 8.4**。下面的库创建和 SQL 执行步骤需要你在本机 MySQL 准备好后操作；应用不会自动建库、执行迁移或改写已有表：

```sql
CREATE DATABASE paytrace CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE paytrace;
SOURCE sql/20260921000100_initial_schema.sql;
SOURCE sql/20260921000200_initial_data.sql;
SOURCE sql/20260922000100_workspace_environments.sql;
-- 然后执行本机生成的 YYYYMMDDHHmmss_private_local_seed.sql（若有）
```

命令行可在项目根目录运行 `mysql -h 127.0.0.1 -u <有建库权限的账号> -p` 后输入以上语句，也可用数据库客户端打开脚本并选择目标库执行。运行应用的账号需具有目标库 SELECT / INSERT / UPDATE 权限；不需要 DROP / DELETE 或建库权限。脚本没有建数据库账号，请使用你本机已有账号或自行创建专用账号。

新库依次执行 initial_schema、initial_data、workspace_environments，再按需执行 private_local_seed；不要执行仅供旧 UTC 库使用的 legacy_utc_to_beijing，也不要直接批量执行整个 sql 目录。基础数据包含 `admin / admin` 登录用户与外卡支付、跨境支付、MSO 三个空间，不带伪造交易和日志。重复执行只补缺失数据，不重置密码、覆盖空间或恢复已归档记录。表结构通过 `schema_migrations` 记录，后续结构调整应新增时间戳 SQL，不修改已部署版本。

旧数据分两部分迁移：

1. **本机文件**：填写配置中的加密密钥后执行 `npm run db:export`，不需要数据库已经启动。读取原 `data/projects.json`、`data/log-sources.json`、`data/ai-config.json`（或原有环境变量指定路径），生成 `sql/YYYYMMDDHHmmss_private_local_seed.sql`。本机已生成的文件可直接执行。私有 SQL 中凭据已加密，但仍可能有内部地址和本地路径，权限 0600、Git 忽略；原文件不修改。自建空间若只在文件中有 ID，会补一个待确认空间，请在页面完善名称。已有数据库配置不覆盖；当前未选择模型时可导入原启用模型。
2. **浏览器数据**：切换 MySQL 后，用此前保存数据的同一个浏览器、同一个网址（localhost 和 127.0.0.1 分开）登录，在“服务配置”点击“导入此浏览器旧数据”。在一个事务中补缺失空间、知识文档和真实排查记录，不覆盖数据库已有名称、文档或记录（包括已保存的空文档），也不恢复归档空间；原浏览器数据保留。旧空间改名可在导入后手工修改。单次上限 4 MB、33 个空间、每空间 2000 条报告；超过时需拆分迁移。

首次登录后可修改初始密码：先停止服务，在 zsh 中执行下面命令，密码从标准输入传入，不放在命令行参数中；新密码需 12–100 个字符，成功后旧会话撤销。改完再启动服务。

```sh
read -s "paytrace_password?新密码: "
printf '%s' "$paytrace_password" | npm run db:password
unset paytrace_password
```

当前只支持**一个 Node 进程连接一个应用库**，服务会取得 MySQL 命名锁阻止重复启动；修改配置请通过页面，手动执行导入 SQL 后重启服务以刷新配置缓存。未做角色权限、多人协作冲突合并、文档版本管理、会话历史清理及归档恢复页面；服务继续只监听 127.0.0.1。

## 数据表与接口

| 表 | 用途与归属 | 主要内容 |
| --- | --- | --- |
| `users` | 全局登录用户 | 唯一账号、显示名、scrypt 哈希、启用状态 |
| `sessions` | 用户会话 | 令牌 SHA256、用户外键、到期和撤销时间 |
| `workspaces` | 按环境隔离的业务空间 | environment（test / production）、名称、说明、业务线、创建人、软删除时间 |
| `workspace_knowledge` | 每空间一份知识配置 | Markdown、旧项目路径、扫描开关的 JSON |
| `investigations` | 空间排查报告 | 搜索标识、证据版本、反馈状态和完整报告 JSON |
| `projects` | 空间项目及分析 | 仓库与分支配置、最后成功链路、文件引用 JSON |
| `log_sources` | 空间 SSH 数据源 | 服务器、日志规则、最近检查 JSON；独立凭据密文 |
| `model_providers` | 全局共享模型 | 接口、模型、配置 JSON；独立 API Key 密文 |
| `app_settings` | 全局单行设置 | 当前模型外键 |
| `schema_migrations` | 全局结构记录 | 已执行 SQL 编号 |

所有表都有 created_at / updated_at，由数据库维护，DATETIME 统一存北京时间（UTC+08:00）；初始化 SQL、私有 SQL 导出和 `scripts/database.mjs` 的连接时区均为 `+08:00`。登录到期、退出及改密码撤销会话使用同一会话时区的 CURRENT_TIMESTAMP，登录有效期仍为 8 小时。页面时间固定按 Asia/Shanghai 展示。报告原始创建时间和 JSON 内业务时间保留带时区的 ISO 格式（可能以 Z 结尾），写入 DATETIME 时由 mysql2 转成北京时间，读取后仍表示同一时刻。

数据库、表和连接统一采用 MySQL 8 默认的 `utf8mb4` / `utf8mb4_0900_ai_ci`，支持中文及 emoji；普通文本比较不区分大小写和重音。需要精确匹配的空间、项目和报告 ID 保留 `ascii_bin`，防止不同大小写的 ID 被当成同一个。HTTP 与 HTML 的 `utf-8` 是网页编码，保持原样。

修改时区不会自动转换已有 DATETIME。如果此前已按 UTC 初始化并写入数据，需要停止服务、备份后，仅对旧 UTC 库执行 `sql/20260921000300_legacy_utc_to_beijing.sql`，将旧日期字段加 8 小时；新建的北京时间库不要执行该脚本。JSON 中带时区的时间不需要迁移。初始化脚本不能代替旧数据转换。

空间外键保证归属，报告按空间与时间、搜索标识建索引；报告的金额等交易信息仍作为证据快照，不建立资金账务表。日志规则和证据形态尚在变化，采用 JSON 保留完整结构，当前没有把每条日志或反馈拆成独立表。模型、项目和 SSH 数据源以实体行为单位保存，不把整个库打包为单个 JSON 文件。所有业务 SQL 参数绑定，动态表名只来自固定白名单。

MySQL 模式新增：`GET /api/workspaces`、`POST /api/workspaces`（新建/编辑）、`POST /api/workspaces/delete`（事务归档）、`/api/data/knowledge`（GET/PUT）、`/api/data/investigations`（GET/POST/DELETE）、`/api/data/investigations/:id`（GET/DELETE）、其 `/feedback`、`/ai` 和 `/followups`（POST），及 `POST /api/import/browser`。空间数据使用 `?workspace=<id>`；旧配置接口保持兼容。`GET /api/storage` 返回当前模式，`/api/auth/login`、`/api/auth/logout` 使用 POST，`/api/auth/session` 使用 GET。除模式检测和登录相关接口外，业务 API 均需登录；写入还校验同源 Origin 和 JSON 内容类型。

## 登录与业务文档

首页和登录页的浏览器标签、左上角品牌标志统一使用黄色角色头像作为项目图标。刷新页面即可看到；若浏览器仍显示旧图标，可关闭标签页后重新打开。

打开页面后先进入登录页，账号 **admin**，密码 **admin**，将模拟验证滑块拖到最右侧后登录。刷新当前标签页保持登录，右上角可退出；退出不会清除业务文档、模型配置或排查记录。未配置数据库时是本地展示入口；MySQL 模式下由服务端验证 scrypt 密码哈希，使用 HttpOnly / SameSite=Strict Cookie 会话，有效期 8 小时，所有业务 API 都要求登录。滑块仍是演示交互，不是真实验证码。角色、空间成员和权限管理暂不实现，登录用户共享空间。初始账号可通过下方密码修改命令更新。

三个工作空间不再预置演示案例或业务文档；已保存的文档（包括主动清空后的空文档）刷新后继续保留。点击“保存知识配置”可保存当前内容。

## 新建工作空间与服务器数据源

- 左侧工作空间下方点击“＋ 新建工作空间”，填写名称、业务说明和业务线，创建后进入服务配置。
- 在“服务器日志数据源”点击“＋ 添加数据源”，填写名称、服务标识（例如 trx）、环境、IP 或主机名、SSH 端口（默认 22）、账号、密码和日志绝对路径。
- 同一服务可添加多台服务器，配置按工作空间隔离，支持编辑和启用 / 停用。
- MySQL 模式将 SSH 密码加密保存在 `log_sources.secret_cipher`，接口不返回密码。本地模式仍保存到 `data/log-sources.json`，权限 0600，文件中为明文。编辑时留空保留密码，更换服务器、端口或账号需重新填写。
- MySQL 模式中空间、文档与排查记录由数据库保存，同一服务下换浏览器登录可看到相同数据；本地模式仍按浏览器分别保存。
- 保存后点击“测试连接”，真实验证 SSH 账号密码及日志文件读取权限。状态保留最近检查时间，修改配置后需重新测试。检查结束即断开，不是常驻连接。
- 已有数据源可点击“复制配置”快速新建副本。副本会带出服务器地址、端口、账号、日志规则、环境和连接方式，名称自动增加“（副本）”；密码不会复制，表单会提示重新输入目标服务器或堡垒机密码。保存前可修改服务器信息，适合为相近服务器复用配置。
- 点击“查询日志”，输入交易流水号或消息 ID，通过 `grep -n -F -m 20 -C 200` 读取配置的日志文件。每个文件最多 20 处匹配、前后各 200 行、256 KB 输出、30 秒超时；截断会明确提示。上下文可能包含其他交易，结果不自动合入沙箱报告或发送给 AI。
- IP 应填写实际可达地址，不能用 `0.0.0.0` 或 `::`。内网服务器需要本机网络 / VPN 可达；支持 SSH 密码认证、ProxyJump 及 usmshell 菜单式堡垒机；日志须为 Linux / Unix 文件。菜单模式暂不支持多因素认证或目标资产二次密码提示。
- 本地需安装 OpenSSH 客户端与 `sshpass`。本次开发机器已具备；其他 macOS 可用 `brew install sshpass`，Linux 安装发行版的 sshpass 软件包。密码通过进程私有管道传入，不进入命令行参数或环境变量。
- 首次连接采用 SSH accept-new 策略，将主机公钥记入 `data/ssh/known_hosts`；后续密钥变化会拒绝连接。需先核实服务器身份，再人工处理对应记录，不自动绕过校验。
- 新工作空间配置并启用日志源后即可跨源检索并分析附近日志；尚未接入交易数据库查询及跨标识自动追踪。
- 服务接口：本机 `GET /api/log-sources?workspace=<id>` 与 `POST /api/log-sources`，返回值不含密码。保存失败不替换原配置。

## 编辑与删除管理

- **工作空间：** 左侧选择空间后，使用“编辑空间 / 删除空间”。内置空间和自建空间均支持；至少保留一个空间。删除当前空间后自动切换至剩余空间，刷新后不会恢复已删除空间。
- **删除范围：** MySQL 模式将空间及关联服务器、项目、排查记录软删除，文档随空间隐藏；原始数据和加密凭据留库，不提供页面恢复入口。本地模式沿用原有文件与浏览器清理逻辑。共用模型、远程日志和 Git 仓库保留。
- **删除失败：** MySQL 模式在事务中完成空间归档与关联数据变更，失败回滚，至少保留一个空间。排查、项目分析或数据源操作进行中时拒绝归档。本地模式分文件保存，部分失败需重试。
- **服务器数据源：** 卡片支持编辑、启停、查询、测试和删除。MySQL 模式归档后不再使用该配置，密文保留；本地模式移除文件中的配置。
- **项目：** 卡片支持新增、编辑、查看分析与删除；删除会一并移除该项目的已保存业务链路。
- **模型服务商：** 支持新增、编辑、查询、测试、启用和删除，名称不能重复。删除当前服务后 AI 停用，已有报告保留。
- **业务文档：** 可导入、编辑、下载或清空；“清空文档”只修改编辑器，点击“保存知识配置”后持久化，刷新不会重新填回默认内容。
- **排查记录：** 支持每页 10 / 20 / 50 条分页、当前页全选与批量删除；翻页或修改筛选会清空勾选。删除最后一页后自动回退有效页码。真实报告的反馈保存成功后留在详情显示“已保存”，失败时保留输入并提示重试；旧沙箱报告保存后返回记录列表。列表每行也支持删除，连同该条记录的反馈、补证及 AI 分析一并移除；不会删除其他空间记录。处理状态与备注继续在报告中编辑。

删除均需二次确认，页面暂不提供撤销；MySQL 模式使用软删除，本地模式仍为原有清理行为。

## 配置项目并生成业务链路

1. 重启 `npm start`，选择目标工作空间，进入“服务配置 → 项目与业务链路 → 添加项目”。
2. 填写项目名称和分析重点。默认使用当前空间已保存的 Markdown，请先在“项目知识来源”保存文档。
3. 需要读取代码时，勾选“启用 Git 代码分析”，选择本地仓库或远程仓库，分支默认 `master`。本地模式填写运行服务这台电脑上的仓库绝对路径。例如跨境项目 `/Users/liuyuhao/IdeaProjects/cross-border`、MSO 项目 `/Users/liuyuhao/IdeaProjects/hk-cb`。本地模式要求分支在本地存在。远程模式填写 HTTP / HTTPS Git 克隆地址（例如 `https://git.example.com/team/project.git`），分支必须在远端存在；仓库使用 main 时请修改分支。
4. 保存配置，再点击卡片上的“AI 分析并保存”。复用“模型服务商”中当前启用的连接，支持兼容接口和 Ollama。配置保存、页面刷新都不会自动扫描或调用模型。
5. 完成后点击“查看业务链路”，在交易排查页的工作空间概览按业务场景查看项目分析。分析会尝试还原触发入口、业务目标、处理环节、关键输入、判断分支、状态变化、副作用、失败处理及成功结果；只有代码或文档能证明的同步调用、异步消息和条件流转才显示为关系，并附文件依据。缺失的信息会明确列在待确认事项中，不会把目录或节点排列冒充执行链路。结果包含模型、分析时间、分支、commit 和采样覆盖范围。

MySQL 模式将项目配置及最后一次成功分析保存在 `projects` 表；本地模式保存到 `data/projects.json`（0600）。两种模式均按空间隔离。旧的浏览器项目路径可展开“此前保存的项目路径”，点击“导入到项目配置”，不会自动读取仓库。Markdown 在 MySQL 模式中保存在 `workspace_knowledge`，旧浏览器文档可主动导入。

代码分析通过本机 Git 只读获取指定分支的**已提交内容**，本地模式不切换当前分支、不修改工作区、不拉取远端或执行项目代码。远程模式每次分析按指定分支浅克隆到系统临时目录，不检出文件、不下载子模块，读取后清理临时副本；获取阶段最多 60 秒。每次最多读取 24 个文件片段、单文件 7,000 字符、总计 90,000 字符；优先业务入口、服务、异步任务和 README，排除常见密钥/环境配置文件、构建目录、测试与符号链接。模型只收到实际选中的片段和候选文件名，不等于全仓扫描；跨文件调用若未同时出现在已读取片段中就无法建立关系，项目内其他敏感信息仍需自行核对，未开启代码分析时不会读取仓库。分析只保存结构化业务摘要、步骤、已证实关系和来源定位，不保存发送给模型的源码文本；关系及业务解释仍需结合完整代码和运行证据复核。

分析显示真实请求阶段和接收进度，只有模型完整返回、结构和文件引用校验通过后才替换结果。失败、断流或停止保留已有完整结果；编辑项目配置会将旧结果标记为“待重分析”。代码或文档更新后需要手动重新分析。文件引用证明该资料已提供给模型，业务解读仍需人工复核。

这些链路用于理解静态业务结构，尚未自动绑定 SSH 数据源、查真实交易或执行跨服务追踪。服务器日志查询继续在对应数据源卡片操作。

私有远程仓库复用运行 Node 服务的系统账号已配置的 Git 凭据管理器。请先用 Git 配好访问账号 / Token；页面不接收 URL 内嵌密码、Token 或查询参数。认证失败会明确提示，也可先手动克隆再选本地模式。HTTP / HTTPS 地址需要本机网络或 VPN 可达；当前不支持 SSH 克隆地址。

接口：本机 `GET /api/projects?workspace=<id>`、`POST /api/projects`（`save` / `analyze`）。代码扫描最多 30 秒，模型阶段默认最多 300 秒，可在服务商编辑窗口调整为 30–3600 秒。分析结果校验业务步骤和关系的结构、下标及来源 ID；旧版已保存结果仍可查看，新版详情会将旧数据缺少的业务字段标为“旧分析未记录”。`scripts/projects.test.mjs` 覆盖关系越界、伪造来源、异步标注、旧结构兼容与模型提示词。测试使用临时仓库和模型桩响应，不会发送用户项目代码。

## 页面切换测试与生产

本地使用同一 MySQL 应用库时，运行一次 `npm start`，登录后点击右上角“切换生产环境 / 切换测试环境”即可。切换会重新加载当前页面，不需要重启 Node 服务或切换端口；当前排查完成后再切换，未保存的编辑需先保存。选择只保存在当前标签页，其他标签页仍使用各自的环境。

首次准备：填写 `config/database.json`，对目标应用库执行 `sql/20260922000100_workspace_environments.sql`，然后重启服务一次。新库先执行前文的建表及基础数据 SQL。未接入 MySQL 或未执行迁移时，页面显示“环境切换待配置”并说明原因，原有本地模式和旧库功能仍可使用。本机现有 `127.0.0.1:3306/paytrace` 已接入并完成此迁移，旧凭据沿用原加密密钥；迁移前私有备份保存在被 Git 忽略的 `data/backups/`。这份本机配置不随仓库分发，其他机器仍需自行准备。

迁移只增加 `workspaces.environment` 字段（默认 `test`）及环境索引，不新增业务表。原空间及其日志源、项目、文档和排查报告保留为测试数据；初始化三个独立的生产空间，名称带“（生产）”，需在生产页面自行配置日志源。各环境通过不同的 `workspace_id` 隔离已有业务表，新建空间归属当前环境。空间名称仍在整个库内唯一。账号、会话和模型服务商全局共用，因此修改模型也影响另一环境；环境切换不表示用户权限隔离。

本地管理入口在两个环境均可配置数据源、查看历史、保存文档与反馈；“生产环境”表示该空间的数据归属，不表示已连接真实生产服务器。只有配置并主动查询相应 SSH 数据源后才会读取服务器日志。旧浏览器数据仅允许从测试页面导入，避免误入生产空间。

技术实现：`frontend/environment.js` 在页面加载时固定 `X-PayTrace-Environment` 请求头，切换后重新加载，不改变在途请求的目标。`scripts/environments.mjs` 校验环境值，`scripts/serve.mjs` 校验日志源、项目、排查与追问的空间归属；`scripts/mysql-api.mjs` 按环境查询空间，并在读写文档、报告和空间时拒绝跨环境 ID。报告额外记录环境快照，持久化仍通过空间外键归属。服务启动时读取迁移版本，未迁移的旧库不开放切换。

单独部署只读生产服务时，仍支持以下命令：

```sh
npm start                 # 本地管理入口，接入 MySQL 后可切换两种环境
npm run start:test        # 同上
npm run start:prod        # 独立生产只读入口，必须提供 .env.prod
```

独立部署应准备 `.env.prod`（参考 `.env.prod.example`）及独立数据库配置；同一应用库仍只允许一个 Node 进程。生产实例通过 `PAYTRACE_ENV=production` 固定只读模式，不能通过请求头切到测试环境绕过限制。若独立库已经执行环境迁移，只读取其中 production 空间；迁移前既有空间默认划为 test，请先明确数据归属再迁移。`PAYTRACE_COUNTERPART_URL` 仅供不同部署之间跳转，本地数据库切换无需填写它。生产日志源支持堡垒机 ProxyJump，认证使用本机 VPN / SSH Agent。

验证：`npm test` 包含环境值校验、跨环境 ID 拒绝、浏览器请求目标固定及外部请求不携带环境头；`MYSQL_TEST_CONFIG=... npm run test:mysql` 在新建隔离库重复执行迁移，验证默认测试归属、生产空空间、并发环境查询、配置/文档/报告隔离和登录会话。测试库保留供检查。


## 接入真实 AI

Node 本地服务调用真实模型，支持 SSH 日志排查及项目业务链路分析。无需 Java；真实 AI、SSH 和 MySQL 均需通过 `npm start` 访问。

1. 运行 `npm start`，打开 http://127.0.0.1:19527 。如果此前启动过旧版本，先停止再重新运行。
2. 进入“服务配置 → 模型服务商”，点击“添加服务商”。可选 DeepSeek、通义千问、Ollama 参考配置，或填写自定义接口。
3. 填写服务商名称、接口根地址、模型名和 API Key，可先“测试连接”，再保存。测试使用与实际分析一致的流式请求，收到完整有效文本才显示成功；小请求测试成功仍不保证大量日志分析成功。勾选“保存后设为当前服务”或点击卡片“启用”即可切换，无需重启。测试不会保存或切换配置。
4. 在“遇到了什么问题？”中直接描述情况，可自然带上交易流水号或订单号，或上传 / 粘贴截图后点击“开始排查”。系统会从问题文本中识别常见交易标识并查询匹配日志，再将日志、截图与已保存的 Markdown 交给模型分析；结果下方的“继续追问”可围绕同一笔交易连续提问。只有截图时可以不提供交易标识。

MySQL 模式将模型配置保存到 `model_providers`，API Key 使用 AES-256-GCM 加密，当前启用模型记录在 `app_settings`；本地模式保存到 `data/ai-config.json`（0600，其中密钥为明文）。页面仅显示是否已有密钥，不回传保存的密钥。留空保留原密钥，更换接口根地址时必须重新填写，可勾选“清除已保存密钥”停用兼容接口。

支持保存多套模型连接，卡片展示当前服务、模型和密钥保存状态，支持编辑、测试及删除备用服务商。所有工作空间共用当前模型，切换只影响后续请求，历史分析保留原模型信息。当前服务商也可删除；删除后 AI 处于未启用状态，需手动启用其他服务商，不自动选择备用连接。原单模型文件自动识别为“默认模型服务”，首次保存时升级为多服务商格式，原有密钥保留。

配置和连接测试默认仅允许本机页面；MySQL 模式可通过下方公网白名单开放 NATAPP 访问，仍需登录。本地模式首次运行可复制 `.env.example` 为 `.env` 配置模型，已有 `data/ai-config.json` 优先。MySQL 模式只读取数据库，不自动导入 `.env` 或 `data/`，需先生成并执行迁移 SQL。

兼容接口配置示例（以 DeepSeek 为例，模型名和服务地址以账号可用配置为准）：

```dotenv
AI_PROVIDER=compatible
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=在本地填写密钥
```

本地 Ollama 配置示例（需要先运行 Ollama 并安装对应模型）：

```dotenv
AI_PROVIDER=ollama
AI_BASE_URL=http://127.0.0.1:11434
AI_MODEL=qwen3:8b
```

兼容模式在根地址后追加 `/chat/completions`；若服务商要求 `/v1`，应在 `AI_BASE_URL` 中包含它。仅支持返回 Chat Completions 文本的接口，不适用于只提供其他协议的服务。



AI 分析通过 SSE 逐步显示，兼容 Chat Completions SSE 和 Ollama NDJSON。进度来自实际请求阶段，分析摘要按事实、可能原因、待核实事项和下一步组织；不展示内部思维链。有效证据引用可以点击查看原文，并高亮对应图谱节点。支持停止；切换页面、工作空间或更新报告时终止旧请求。只有完整接收且证据版本一致的结果才保存，断流、超时和停止均保留原报告。服务商若返回完整 JSON，会明确说明并整段展示，不模拟打字流。

历史演示资料（案例已移除）：[证据图谱与流式分析演示](docs/证据图谱与流式分析演示.md)。

模型配置状态不代表连接成功，实际调用成功后报告才标记为真实 AI。分析结果按当前模式保存到 MySQL 或浏览器，并包含在报告导出中；失败时保留原有规则报告，不使用模拟文本冒充模型输出。单次模型分析超时默认 300 秒，可在“服务配置 → 编辑服务商 → 分析超时（秒）”设置为 30–3600 秒；随服务商保存，旧配置默认 300 秒，保存后新请求生效。前端沿用服务端超时并支持手动停止；服务商连接测试也使用该超时：卡片测试读取已保存配置，编辑窗口测试使用当前填写值，不会自动保存；测试提示同步显示秒数。`scripts/serve.mjs` 复用模型适配器的配置超时，`frontend/app.js` 的测试请求在该时长上额外留 5 秒接收错误响应，普通配置请求保持 65 秒。分析最多两个并发调用，每分钟最多十次。

AI 请求可能计费；点击按钮会将所列数据、所附截图和已保存 Markdown 发送给所配置的服务。项目代码分析通过独立的“项目与业务链路”入口发起。

模型在接收过程中返回错误时，会按可识别的错误类型提示认证、额度、上下文上限、参数不兼容或服务故障；无法识别时明确提示查看服务商请求记录，不再笼统显示“生成中断”。`scripts/ai.mjs` 对 SSE、Ollama NDJSON 和完整 JSON 响应中的错误统一分类，不回显原始服务商错误正文，避免暴露密钥或请求内容。`scripts/serve.mjs` 的连接测试复用 `analyzeStream`，不保存测试文本或修改模型配置。已有失败报告保留原提示，需要重新测试或排查才能得到新的提示。

检查适配器和配置：`node --test scripts/ai.test.mjs scripts/stream.test.mjs scripts/model-config.test.mjs`。适配器测试使用桩响应，验证配置超时、流式完整性、错误分类和敏感信息不回显；配置测试验证卡片、编辑窗口和旧配置的浏览器等待时长。实际模型连通性需填写有效配置后验证。

需要 Node.js 20 或更高版本，先运行 `npm install` 安装 mysql2；无需 Java，本地模式无需数据库；远程 SSH 功能还需要本机 ssh 与 sshpass。可在服务配置中测试模型、查询真实日志及运行项目 AI 分析。

## 直接打开

双击 `frontend/index.html` 仅能进入本地演示入口；实际排查和数据库功能请运行下方 HTTP 服务。

## 启动 HTTP 服务

需要通过本地地址访问时，在项目根目录运行：

```sh
npm install
npm start
```

访问 http://127.0.0.1:19527 。`npm start` 启动测试环境，配置优先读取 `.env.test`，不存在时读取 `.env`，两者都不存在时读取 `.env.test.example`；这些文件不会叠加加载，Shell 环境变量优先于文件。`scripts/serve.mjs` 默认监听本机端口 19527。使用 SSH 时还需 ssh 与 sshpass。端口冲突可用 `PORT=19528 npm start`。

本机测试可从 `.env.test.example` 复制生成 `.env.test`，保持 `PUBLIC_ORIGINS=` 为空。若启动报“PUBLIC_ORIGINS 需要 MySQL 模式的服务端登录验证”，说明当前使用本地存储却配置了公网来源；本机使用应在当前环境配置中留空该项，公网访问则需先配置 MySQL。测试环境默认仍读取 `config/database.json`；需要独立测试库时设置 `DATABASE_CONFIG_FILE`。生产环境使用 `npm run start:prod`，必须准备 `.env.prod`。


## NATAPP 内网穿透访问

在当前启动使用的环境文件中（测试环境优先 `.env.test`，生产环境 `.env.prod`）添加公网来源地址，然后重启对应服务：

```dotenv
PUBLIC_ORIGINS=http://your-domain.natappfree.cc
```

将地址替换成 NATAPP 当前分配的地址，NATAPP 转发到 `127.0.0.1:19527`，保留原始 Host。用该地址打开页面，登录后即可加载工作空间和使用配置、日志查询、排查及追问。免费域名变化后需更新配置并重启。HTTPS 地址必须以 `https://` 单独配置；多个来源用逗号分隔，不包含末尾斜杠、路径或通配符。启用 HTTPS 时使用 NATAPP 实际提供的 HTTPS 地址。

公网访问要求已经配置 MySQL，因为本地展示登录不提供服务端身份验证；本地模式设置白名单会拒绝启动。对外使用前请通过 `npm run db:password` 修改初始密码，HTTP 隧道不加密登录凭据，处理真实数据建议使用 HTTPS。

`scripts/request-access.mjs` 校验本机转发连接、实际 Host 和精确来源白名单，支持 NATAPP 的代理转发头，但不使用这些头决定放行。`scripts/serve.mjs` 对所有 API 应用访问校验；业务 API 保留 MySQL 会话检查，写操作保留同源 Origin 与 JSON 检查。监听地址仍为 `127.0.0.1`。不配置 `PUBLIC_ORIGINS` 时保持仅本机访问，无数据库结构变更。单元验证运行 `node --test scripts/request-access.test.mjs`，完整回归运行 `npm test`。

## 工作空间与业务链路

测试环境保留外卡支付、跨境支付、MSO 三个工作空间；完成环境迁移后，生产环境拥有对应的三个独立空空间。支持新建、编辑与删除，各空间文档、项目、日志源和排查记录独立，模型配置共用。

## 可以体验

- 在服务配置中添加服务器，测试 SSH 连接并按流水号查询真实日志。
- 导入或编写 Markdown 业务文档，配置本地或远程项目。
- 配置模型服务商，运行项目 AI 分析并保存业务链路。

交易排查已支持按标识查询配置的 SSH 日志，再调用模型生成报告；尚未接入交易数据库，不会编造交易金额、商户或支付状态。

提问区采用一体化圆角输入框，截图缩略图显示在文字上方；点击左下角加号、直接粘贴或拖入图片即可添加，点击缩略图右上角 × 可以移除，最多 10 张 PNG / JPEG / WebP。系统会从问题文本中识别常见交易流水号或订单号；没有标识时可只依据截图分析。原图每张最多 10 MB、4000 万像素，浏览器将长边缩至最多 2000 像素并压缩至每张 500 KB 以内；查询失败仍可依据截图分析。截图会发送给当前模型，需要配置支持视觉输入的模型和接口。报告可点击查看原图（上传处理后的版本）、重新分析、导出带内嵌图片的 Markdown；继续追问会附带原始截图，追问输入框暂不支持追加新图。

`frontend/image-upload.js` 负责加号选图、粘贴、拖拽、缩放和预览，上传处理中或排查期间禁用附件操作；`frontend/images.js` 在浏览器与服务端共用数量、大小、Base64、图片类型和文件头校验，只接受内嵌图片，不抓取外部图片 URL。兼容接口发送 `image_url` 消息，Ollama `/api/chat` 使用 `images` Base64 数组。图片保存在既有 `investigations.payload.images` JSON；本地模式随报告存入 localStorage，无需新增表、字段或迁移 SQL。浏览器容量不足时明确提示保存失败，请导出备份。排查、追问及单份报告保存请求上限为 10 MB（包含 Base64 图片及文字）；其他数据接口仍为 4 MB；排查 SSE 完成事件不重复返回图片，浏览器以本次提交的图片快照补回报告，服务端入库保留完整图片。切换空间和退出会清空尚未提交的截图。

MySQL 模式中报告由服务器在流式响应完成前保存，刷新或更换浏览器可读取；保存失败会明确报错。浏览器重试提交同一报告不会覆盖已保存反馈，也不会恢复已归档记录。本地模式继续使用 localStorage。

排查记录支持按流水号、商户、问题或结论搜索，按处理状态和 AI 分析状态筛选，并显示当前空间的记录汇总。AI 输出中的有效证据编号（如 `[E1]`）可点击展开对应日志；未匹配的编号只显示文本，不链接到其他证据。

真实报告可查看日志证据与查询覆盖情况、导出 Markdown 并填写处理反馈。“处理结论”提供“已解决／需要研发介入／判断不正确”三种可选卡片，按结果显示填写引导，并可点击“插入填写提纲”追加到备注末尾。切换结果保留输入，备注选填、最多 2000 字；插入后超限会提示精简，不截断内容。区域显示未保存、保存中、已保存或保存失败状态。“保存反馈”仅记录人工反馈，成功后留在当前报告；“重新查询并分析”重新获取日志并生成新报告，保留当前报告与已保存反馈。有未保存的修改时需先保存；反馈保存期间禁止启动新的排查或追问。追问更新报告时保留反馈草稿，Markdown 导出包含已保存的处理结论。在“继续追问”输入后点击“发送追问”，回答会逐步显示，也可以停止；首次 AI 分析失败仍可追问。普通追问使用原有日志、原始截图、原始问题、首次成功分析、当前已保存的业务文档、最近一次补查证据和最近对话；追问“查附近日志”“扩大范围”“补查日志”等会按原检索标识重新查询当前空间全部启用的日志源，并对命中文件逐级扩大范围。每轮补查证据与覆盖单独保存、展示和导出，使用独立引用编号，不改写原报告证据。也可使用“重新查询并分析”生成独立的新报告。只有截图时模型可以解释截图内容，但不能据此确认后台交易状态；没有日志和截图时模型只能说明证据不足。

“继续追问”输入区也支持点击 ＋ 选择图片、直接粘贴截图或拖入图片，每轮最多 10 张；可只发截图，不必填写文字。发送前可预览和移除，处理失败或停止回答时保留文字与截图，发送完成后在该轮对话中查看并点击放大。

完整追问（含每轮截图）随排查记录保存，重新打开可继续，导出 Markdown 包含全部已保存对话、各轮截图及当前未保存的完整回答。失败或停止保留输入和已有对话，未完成的输出不作为后续上下文；完整回答保存失败时显示“重试保存”，保存前不能继续发送。切换页面或退出会停止当前追问。单条问题最多 4000 字符；模型收到最近最多 12 轮、合计最多 60000 字符、历史追问图片最多 10 张的完整问答（原始截图与本轮新图各最多 10 张另计），较早对话保留在报告中，未加入上下文时页面提示。

`POST /api/investigations/followup/stream` 提供追问 SSE，复用模型超时、同源检查、登录校验和调用限流。MySQL 模式从服务端读取所属空间的报告和文档，完成后将问答追加到现有 `investigations.payload.followups` JSON；本地模式通过 `/investigations/:id/followups` 浏览器接口保存。无需新增数据库表、字段或迁移 SQL。追加按证据版本及现有轮数检查冲突，重复保存同一问答 ID 幂等，不覆盖反馈；页面更新回答时保留未提交的反馈草稿。`frontend/followup-data.js` 共享追加校验与上下文裁剪，`frontend/followup-ui.js` 实现交互并复用 `frontend/image-upload.js` 的图片输入组件，`scripts/followup.mjs` 构造包含原图、最近对话图片和本轮新图的多模态消息。新增图片保存在既有 `followups[].images` JSON 中，旧文字记录继续兼容；格式、压缩与大小限制和初次排查相同。追问流请求上限 24 MB，单轮追加保存上限 10 MB；SSE 完成事件不回传图片，由前端从本轮已校验的附件补回，避免大图触发流事件长度限制。

Markdown 点击“保存知识配置”后按当前模式保存到数据库或浏览器，页面展示保存位置和时间；保存空文档也是有效操作。可下载 `.md` 备份。当前只保存最新文档，不提供文档版本管理或 OSS。

## 日志目录与相对路径

日志数据源支持完整绝对路径、`~/` 主目录路径及相对文件路径。相对文件路径以“日志目录”为基准；目录留空时，以远端 SSH 账号主目录为基准。例如目录为 `/data/logs`、文件为 `trx-console.log`，实际查询 `/data/logs/trx-console.log`。绝对文件路径及 `~/` 文件路径忽略目录配置，已有绝对路径配置保持兼容。

同一服务器可添加多条日志规则，支持具体文件及当前目录的 `*` / `?` 文件名通配符，不递归子目录。终端中的 `logs` 可能是目录跳转别名或函数；跳转后执行 `pwd` 得到的实际路径可用于日志目录，应用不执行这些别名。


交易排查入口已连接真实日志与 AI：在服务配置中配置模型和当前空间的日志数据源并启用，保存业务文档后，在“遇到了什么问题？”中描述问题并点击「开始排查」。系统从问题文本中识别常见交易标识，依次查询当前空间启用的日志源，将关键词命中行、附近日志与多行异常堆栈连同问题、截图和业务文档发送给模型，报告按存储模式保存在 MySQL 或当前浏览器的排查记录中，支持导出和反馈。未识别到标识且未附截图时不会调用模型；有截图时可继续分析图片，部分查询失败、内容截断和 AI 调用失败会保留在报告中。查询仅覆盖配置的文件，每个文件最多匹配 20 处，不查询交易数据库，也不自动执行资金操作。


使用时只需输入订单号和问题。系统先到当前空间全部启用日志源中按字面量定位，再读取命中文件前后各 100 行；未取得同时间、同线程的候选异常时，依次扩大到 200、500、1000 行。不会再丢弃不带订单号的异常和堆栈。命中行与附近原文分开展示，模型必须核实时间、环境、线程和交易关联，避免串单；发现候选异常不等于已确认根因。报告展示实际尝试范围、停止原因、读取失败和容量遗漏。扩大范围的追问跳过候选异常早停，但文件没有新增内容或达到输出上限时仍停止。

技术实现：`scripts/log-evidence.mjs` 统一初次排查及追问取证；`scripts/ssh-logs.mjs` 对上下文行数使用 0 / 100 / 200 / 500 / 1000 白名单，采用带行号的 `grep -F`，仅对服务端配置或本轮发现的命中文件补查，不执行模型提供的命令。每次 SSH 最多 256 KB、30 秒；每台服务器单轮最多 20 个文件、120 秒。每轮报告最多 100 个证据块，命中原文和上下文总计约 45000 字符，每块上下文最多 14000 字符；优先保留命中位置和同线程、前后 5 秒内的候选异常堆栈，其他附近行按距离纳入并标记缺口。重叠行去重，文件轮转后重新检索原标识而非复用旧行号。尚未实现跨标识自动追踪、自动查交易数据库或无限扩展；达到限制仍无结论时会明确覆盖不足。

补查快照保存于既有 `investigations.payload.followups[].logQuery` JSON，本地模式保存在同一报告的 localStorage；无需数据库迁移。`frontend/followup-data.js` 校验并保存快照，`frontend/followup-ui.js` 展示与导出本轮原文。`scripts/log-evidence.test.mjs` 和追问回归覆盖无订单号的异常堆栈、跨源定位顺序、逐级扩展、无关线程、读取失败、截断、取消、命令范围校验及快照保存；运行 `npm test` 验证。

一台服务器可配置多条日志规则，共用地址、SSH 账号和密码。日志目录填写实际路径（登录后执行 `pwd` 获取）；规则支持具体文件和当前目录中的 `*` / `?` 文件名通配符。例如 `*-console.log` 匹配 `trx-console.log`、`daemon-console.log`、`merchant-console.log` 和 `boss-console.log`，不匹配 `trx-console.2026-09-20.log`。可逐行指定服务，留空则从文件名识别。每台服务器最多查询 20 个文件，重复文件去重，查询保留每个文件的失败情况和服务来源。系统从问题中识别出的搜索标识会用于跨服务日志查询并交给 AI；暂不自动扩展订单号、渠道流水号等不同标识之间的映射。旧单文件配置兼容。


### usmshell 菜单式堡垒机

在运行 PayTrace 的电脑上先连接 VPN。添加日志数据源时选择“菜单式堡垒机（usmshell）”：目标服务器地址、端口和账号填写资产列表中的机器；堡垒机地址、端口和账号填写最初登录菜单的连接信息。“登录密码”填写堡垒机密码，沿用现有密码字段的加密存储，不需要新增数据库表或迁移。

程序申请 SSH 终端，识别 `[usmshell]` 菜单，发送按目标地址生成的 `:ssh 用户@主机:端口` 指令，等待目标 shell，再执行固定日志检查或查询。无需填写资产编号，不支持任意自定义登录脚本。目标资产必须由堡垒机托管并自动登录；额外密码或验证码不自动提交。菜单差异、网络不可达或无法识别 shell 会失败或超时，不能把保存成功当作连接成功。

日志目录填写进入目标机器后 `pwd` 的绝对路径，日志规则填写实际文件名或文件名通配符，不填写 `cd` / `tail`。菜单模式已用模拟交互测试，实际堡垒机需连接 VPN 并填写密码后在页面测试连接。
