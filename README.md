# PayTrace 本地工作台

产品交付文档：[PayTrace 支付交易智能排障平台建设方案](docs/PayTrace演示说明与后续技术架构.md)。精简汇报版，适合约 7 分钟介绍业务痛点、核心方案、差异化亮点及落地范围。

## 登录与业务文档

打开页面后先进入登录页，账号 **admin**，密码 **admin**，将模拟验证滑块拖到最右侧后登录。刷新当前标签页保持登录，右上角可退出；退出不会清除业务文档、模型配置或排查记录。此功能是本地展示用的前端入口与模拟滑块，不提供服务端鉴权，后续生产环境需接入真实身份认证。

三个工作空间不再预置演示案例或业务文档；已保存的文档（包括主动清空后的空文档）刷新后继续保留。点击“保存知识配置”可保存当前内容。

演示交易、预设日志和报告已从运行页面移除；刷新后会清理浏览器中的旧演示报告，保留其他记录、已保存文档及配置。

## 新建工作空间与服务器数据源

- 左侧工作空间下方点击“＋ 新建工作空间”，填写名称、业务说明和业务线，创建后进入服务配置。
- 在“服务器日志数据源”点击“＋ 添加数据源”，填写名称、服务标识（例如 trx）、环境、IP 或主机名、SSH 端口（默认 22）、账号、密码和日志绝对路径。
- 同一服务可添加多台服务器，配置按工作空间隔离，支持编辑和启用 / 停用。
- 密码保存到本机 `data/log-sources.json`，文件权限 0600，密码不回传页面、不进入 localStorage；本机文件中的密码为明文。编辑时留空保留密码，更换服务器、端口或账号需重新填写。
- 工作空间定义保存在浏览器 `paytrace.custom-workspaces.v1`；文档与记录沿用各自命名空间。刷新可恢复，换浏览器不会自动同步工作空间定义。
- 保存后点击“测试连接”，真实验证 SSH 账号密码及日志文件读取权限。状态保留最近检查时间，修改配置后需重新测试。检查结束即断开，不是常驻连接。
- 点击“查询日志”，输入交易流水号或消息 ID，通过 `grep -n -F -m 20 -C 200` 读取单个配置文件。最多 20 处匹配、前后各 200 行、256 KB 输出、30 秒超时；截断会明确提示。上下文可能包含其他交易，结果不自动合入沙箱报告或发送给 AI。
- IP 应填写实际可达地址，不能用 `0.0.0.0` 或 `::`。内网服务器需要本机网络 / VPN 可达；仅支持 SSH 密码认证及 Linux / Unix 日志文件，暂不支持私钥、跳板机与多因素登录。
- 本地需安装 OpenSSH 客户端与 `sshpass`。本次开发机器已具备；其他 macOS 可用 `brew install sshpass`，Linux 安装发行版的 sshpass 软件包。密码通过进程私有管道传入，不进入命令行参数或环境变量。
- 首次连接采用 SSH accept-new 策略，将主机公钥记入 `data/ssh/known_hosts`；后续密钥变化会拒绝连接。需先核实服务器身份，再人工处理对应记录，不自动绕过校验。
- 新工作空间仍未接入真实交易查询及自动跨服务排障；可以先使用服务配置里的远程日志查询。
- 服务接口：本机 `GET /api/log-sources?workspace=<id>` 与 `POST /api/log-sources`，返回值不含密码。保存失败不替换原配置。

## 编辑与删除管理

- **工作空间：** 左侧选择空间后，使用“编辑空间 / 删除空间”。内置空间和自建空间均支持；至少保留一个空间。删除当前空间后自动切换至剩余空间，刷新后不会恢复已删除空间。
- **删除范围：** 确认后删除该空间在本机的服务器配置及密码、项目及分析结果，以及当前浏览器的业务文档、样例服务开关和排查记录。共用模型配置、远程日志文件与 Git 仓库保留。工作空间定义仍按浏览器保存，其他浏览器的定义不会自动同步。
- **删除失败：** 本机配置分文件清理，若部分保存失败，空间入口保留并提示重试；重试可完成剩余清理。项目分析或数据源操作进行中时拒绝删除。删除需通过 `npm start` 启动的页面执行。
- **服务器数据源：** 卡片支持编辑、启停、查询、测试和删除。删除同时移除本机保存的密码。
- **项目：** 卡片支持新增、编辑、查看分析与删除；删除会一并移除该项目的已保存业务链路。
- **模型服务商：** 支持新增、编辑、查询、测试、启用和删除，名称不能重复。删除当前服务后 AI 停用，已有报告保留。
- **业务文档：** 可导入、编辑、下载或清空；“清空文档”只修改编辑器，点击“保存知识配置”后持久化，刷新不会重新填回默认内容。
- **排查记录：** 支持每页 10 / 20 / 50 条分页、当前页全选与批量删除；翻页或修改筛选会清空勾选。删除最后一页后自动回退有效页码。反馈保存成功后返回记录列表，失败时保留详情与输入。列表每行也支持删除，连同该条记录的反馈、补证及 AI 分析一并移除；不会删除其他空间记录。处理状态与备注继续在报告中编辑。

删除均需二次确认，不可撤销，请先按需导出文档或报告。

## 配置项目并生成业务链路

1. 重启 `npm start`，选择目标工作空间，进入“服务配置 → 项目与业务链路 → 添加项目”。
2. 填写项目名称和分析重点。默认使用当前空间已保存的 Markdown，请先在“项目知识来源”保存文档。
3. 需要读取代码时，勾选“启用 Git 代码分析”，选择本地仓库或远程仓库，分支默认 `master`。本地模式填写运行服务这台电脑上的仓库绝对路径。例如跨境项目 `/Users/liuyuhao/IdeaProjects/cross-border`、MSO 项目 `/Users/liuyuhao/IdeaProjects/hk-cb`。本地模式要求分支在本地存在。远程模式填写 HTTP / HTTPS Git 克隆地址（例如 `https://git.example.com/team/project.git`），分支必须在远端存在；仓库使用 main 时请修改分支。
4. 保存配置，再点击卡片上的“AI 分析并保存”。复用“模型服务商”中当前启用的连接，支持兼容接口和 Ollama。配置保存、页面刷新都不会自动扫描或调用模型。
5. 完成后点击“查看业务链路”，在交易排查页的工作空间概览查看项目摘要、业务线、处理链路、文件引用与待确认事项。结果包含模型、分析时间、分支、commit 和采样覆盖范围。

项目配置与成功的分析结果保存在本机 `data/projects.json`，按工作空间隔离，文件权限 0600；不需要数据库。旧的浏览器项目路径可展开“此前保存的项目路径”，点击“导入到项目配置”，不会自动读取仓库。原有 Markdown 仍保存在浏览器。

代码分析通过本机 Git 只读获取指定分支的**已提交内容**，本地模式不切换当前分支、不修改工作区、不拉取远端或执行项目代码。远程模式每次分析按指定分支浅克隆到系统临时目录，不检出文件、不下载子模块，读取后清理临时副本；获取阶段最多 60 秒。每次最多读取 24 个文件片段、单文件 7,000 字符、总计 90,000 字符；优先业务入口、服务、异步任务和 README，排除常见密钥/环境配置文件、构建目录、测试与符号链接。模型只收到实际选中的片段和候选文件名，不等于全仓扫描；项目内其他敏感信息仍需自行核对，未开启代码分析时不会读取仓库。

分析显示真实请求阶段和接收进度，只有模型完整返回、结构和文件引用校验通过后才替换结果。失败、断流或停止保留已有完整结果；编辑项目配置会将旧结果标记为“待重分析”。代码或文档更新后需要手动重新分析。文件引用证明该资料已提供给模型，业务解读仍需人工复核。

这些链路用于理解静态业务结构，尚未自动绑定 SSH 数据源、查真实交易或执行跨服务追踪。服务器日志查询继续在对应数据源卡片操作。

私有远程仓库复用运行 Node 服务的系统账号已配置的 Git 凭据管理器。请先用 Git 配好访问账号 / Token；页面不接收 URL 内嵌密码、Token 或查询参数。认证失败会明确提示，也可先手动克隆再选本地模式。HTTP / HTTPS 地址需要本机网络或 VPN 可达；当前不支持 SSH 克隆地址。

接口：本机 `GET /api/projects?workspace=<id>`、`POST /api/projects`（`save` / `analyze`）。代码扫描最多 30 秒，模型阶段最多 60 秒。测试使用临时仓库和模型桩响应，不会发送用户项目代码。

## 接入真实 AI

现已提供可选的真实模型调用：前端继续使用模拟交易，Node 本地服务代为调用模型。无需 Java，双击 HTML 仍可体验模拟流程，但真实 AI 必须通过 `npm start` 访问。

1. 运行 `npm start`，打开 http://127.0.0.1:5173 。如果此前启动过旧版本，先停止再重新运行。
2. 进入“服务配置 → 模型服务商”，点击“添加服务商”。可选 DeepSeek、通义千问、Ollama 参考配置，或填写自定义接口。
3. 填写服务商名称、接口根地址、模型名和 API Key，可先“测试连接”，再保存。勾选“保存后设为当前服务”或点击卡片“启用”即可切换，无需重启。测试不会保存或切换配置。
4. 完成一次交易排查，点击图谱右上角或“AI 证据分析”中的“AI 分析”。模型使用问题、沙箱交易、匹配日志与已保存的 Markdown，逐步输出分析摘要。

模型配置保存到本机 `data/ai-config.json`（已被 Git 忽略），文件权限为当前用户读写；其中密钥是明文，应保护电脑及备份。页面仅显示是否已有密钥，不回传保存的密钥。留空保留原密钥，更换接口根地址时必须重新填写，可勾选“清除已保存密钥”停用兼容接口。

支持保存多套模型连接，卡片展示当前服务、模型和密钥保存状态，支持编辑、测试及删除备用服务商。所有工作空间共用当前模型，切换只影响后续请求，历史分析保留原模型信息。当前服务商也可删除；删除后 AI 处于未启用状态，需手动启用其他服务商，不自动选择备用连接。原单模型文件自动识别为“默认模型服务”，首次保存时升级为多服务商格式，原有密钥保留。

配置和连接测试仅允许本机 localhost/127.0.0.1 页面访问。首次运行也可以复制 `.env.example` 为 `.env` 配置模型；如果存在 `data/ai-config.json`，优先使用页面保存的配置。文档和排查记录依然保存在浏览器，不需要数据库。

兼容接口配置示例（以 DeepSeek 为例，模型名和服务地址以账号可用配置为准）：

```dotenv
AI_PROVIDER=compatible
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=在本地填写密钥
```

本地 Ollama 配置示例（需要先运行 Ollama 并安装对应模型）：

```dotenv
AI_PROVIDER=ollama
AI_BASE_URL=http://127.0.0.1:11434
AI_MODEL=qwen3:8b
```

兼容模式在根地址后追加 `/chat/completions`；若服务商要求 `/v1`，应在 `AI_BASE_URL` 中包含它。仅支持返回 Chat Completions 文本的接口，不适用于只提供其他协议的服务。



AI 分析通过 SSE 逐步显示，兼容 Chat Completions SSE 和 Ollama NDJSON。进度来自实际请求阶段，分析摘要按事实、可能原因、待核实事项和下一步组织；不展示内部思维链。有效证据引用可以点击查看原文，并高亮对应图谱节点。支持停止；切换页面、工作空间或更新报告时终止旧请求。只有完整接收且证据版本一致的结果才保存，断流、超时和停止均保留原报告。服务商若返回完整 JSON，会明确说明并整段展示，不模拟打字流。

历史演示资料（案例已移除）：[证据图谱与流式分析演示](docs/证据图谱与流式分析演示.md)。

模型配置状态不代表连接成功，实际调用成功后报告才标记为真实 AI。分析结果保存到浏览器并包含在报告导出中；失败时保留原有规则报告，不使用模拟文本冒充模型输出。单次请求超时为 60 秒，最多两个并发调用，每分钟最多十次。

AI 请求可能计费；点击按钮会将所列数据和已保存 Markdown 发送给所配置的服务。项目代码分析通过独立的“项目与业务链路”入口发起。

检查适配器和配置：`node --test scripts/ai.test.mjs scripts/model-config.test.mjs`。适配器测试使用桩响应，实际模型连通性需填写有效配置后验证。

基础页面和 AI 调用需要 Node.js 20 或更高版本，无需 npm 依赖、Java 或数据库；远程 SSH 功能还需要本机 ssh 与 sshpass。可在服务配置中测试模型、查询真实日志及运行项目 AI 分析。

## 可以体验

- 在服务配置中添加服务器，测试 SSH 连接并按流水号查询真实日志。
- 导入或编写 Markdown 业务文档，配置本地或远程项目。
- 配置模型服务商，运行项目 AI 分析并保存业务链路。

真实交易查询、日志到排查报告的自动分析流程尚未接通，因此交易排查页显示接入提示，不生成预设结论。

记录保存在当前浏览器 localStorage，不同浏览器或地址互不共享。清理站点数据会删除记录；存储不可用或空间不足时明确提示未保存，保留原有记录。

排查记录支持按流水号、商户、问题或结论搜索，按处理状态和 AI 分析状态筛选，并显示当前空间的记录汇总。AI 输出中的有效证据编号（如 `[E1]`）可点击展开对应日志；未匹配的编号只显示文本，不链接到其他证据。

报告展示、导出与反馈组件保留，等待后续真实报告流程接入。

Markdown 业务文档点击“保存知识配置”后持久化到当前浏览器 localStorage，页面展示保存时间，刷新后可读取。支持下载当前编辑内容为 `.md` 备份；存储失败会明确提示未保存。后续计划由 Java 后端接入私有 OSS 保存正文，数据库维护文档元信息和版本，详见产品建设方案。

## 日志目录与相对路径

日志数据源支持完整绝对路径、`~/` 主目录路径及相对文件路径。相对文件路径以“日志目录”为基准；目录留空时，以远端 SSH 账号主目录为基准。例如目录为 `/data/logs`、文件为 `trx-console.log`，实际查询 `/data/logs/trx-console.log`。绝对文件路径及 `~/` 文件路径忽略目录配置，已有绝对路径配置保持兼容。

同一目录中的 `trx-console.log`、`daemon-console.log`、`merchant-console.log`、`boss-console.log` 分别配置为数据源。每项对应一个具体文件，不自动匹配通配符或轮转文件。终端中的 `logs` 可能是目录跳转别名或函数；跳转后执行 `pwd` 得到的实际路径可用于日志目录，应用不执行这些别名。


交易排查入口已连接真实日志与 AI：在服务配置中配置模型和当前空间的日志数据源并启用，保存业务文档后，输入流水号或订单号，点击「开始排查」。系统依次查询当前空间启用的日志源，将关键词命中行与业务文档发送给模型，报告保存在当前浏览器的排查记录中，支持导出和反馈。未命中时不调用模型；部分查询失败、内容截断和 AI 调用失败会保留在报告中。查询仅覆盖配置的文件，每个源最多匹配 20 处，不查询交易数据库，也不自动执行资金操作。


一台服务器可配置多条日志规则，共用地址、SSH 账号和密码。日志目录填写实际路径（登录后执行 `pwd` 获取）；规则支持具体文件和当前目录中的 `*` / `?` 文件名通配符。例如 `*-console.log` 匹配 `trx-console.log`、`daemon-console.log`、`merchant-console.log` 和 `boss-console.log`，不匹配 `trx-console.2026-09-20.log`。可逐行指定服务，留空则从文件名识别。每台服务器最多查询 20 个文件，重复文件去重，查询保留每个文件的失败情况和服务来源。相同搜索标识的跨服务日志一起交给 AI；暂不自动扩展订单号、渠道流水号等不同标识之间的映射。旧单文件配置兼容。
