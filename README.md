# PayTrace 本地演示

产品交付文档：[PayTrace 支付交易智能排障平台建设方案](docs/PayTrace演示说明与后续技术架构.md)。精简汇报版，适合约 7 分钟介绍业务痛点、核心方案、差异化亮点及落地范围。

## 接入真实 AI

现已提供可选的真实模型调用：前端继续使用模拟交易，Node 本地服务代为调用模型。无需 Java，双击 HTML 仍可体验模拟流程，但真实 AI 必须通过 `npm start` 访问。

1. 运行 `npm start`，打开 http://127.0.0.1:5173 。如果此前启动过旧版本，先停止再重新运行。
2. 进入“服务配置 → 模型服务商”，点击“添加服务商”。可选 DeepSeek、通义千问、Ollama 参考配置，或填写自定义接口。
3. 填写服务商名称、接口根地址、模型名和 API Key，可先“测试连接”，再保存。勾选“保存后设为当前服务”或点击卡片“启用”即可切换，无需重启。测试不会保存或切换配置。
4. 完成一次交易排查，点击图谱右上角或“AI 证据分析”中的“AI 分析”。模型使用问题、沙箱交易、匹配日志与已保存的 Markdown，逐步输出分析摘要。

模型配置保存到本机 `data/ai-config.json`（已被 Git 忽略），文件权限为当前用户读写；其中密钥是明文，应保护电脑及备份。页面仅显示是否已有密钥，不回传保存的密钥。留空保留原密钥，更换接口根地址时必须重新填写，可勾选“清除已保存密钥”停用兼容接口。

支持保存多套模型连接，卡片展示当前服务、模型和密钥保存状态，支持编辑、测试及删除备用服务商。所有工作空间共用当前模型，切换只影响后续请求，历史分析保留原模型信息。当前服务商需先切换后才能删除。原单模型文件自动识别为“默认模型服务”，首次保存时升级为多服务商格式，原有密钥保留。

配置和连接测试仅允许本机 localhost/127.0.0.1 页面访问。首次运行也可以复制 `.env.example` 为 `.env` 配置模型；如果存在 `data/ai-config.json`，优先使用页面保存的配置。文档和排查记录依然保存在浏览器，不需要数据库。

兼容接口配置示例（以 DeepSeek 为例，模型名和服务地址以账号可用配置为准）：

```dotenv
AI_PROVIDER=compatible
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=在本地填写密钥
```

本地 Ollama 配置示例（需要先运行 Ollama 并安装对应模型）：

```dotenv
AI_PROVIDER=ollama
AI_BASE_URL=http://127.0.0.1:11434
AI_MODEL=qwen3:8b
```

兼容模式在根地址后追加 `/chat/completions`；若服务商要求 `/v1`，应在 `AI_BASE_URL` 中包含它。仅支持返回 Chat Completions 文本的接口，不适用于只提供其他协议的服务。

证据图谱已覆盖三个空间的九个案例：点击节点查看精确关联证据，红色为异常记录，黄色为待核实，灰色虚线为证据缺口。连线表示预期路径，不证明步骤已执行；相邻交易日志不会参与节点状态判断。商户补证后图谱随报告更新。

AI 分析通过 SSE 逐步显示，兼容 Chat Completions SSE 和 Ollama NDJSON。进度来自实际请求阶段，分析摘要按事实、可能原因、待核实事项和下一步组织；不展示内部思维链。有效证据引用可以点击查看原文，并高亮对应图谱节点。支持停止；切换页面、工作空间或更新报告时终止旧请求。只有完整接收且证据版本一致的结果才保存，断流、超时和停止均保留原报告。服务商若返回完整 JSON，会明确说明并整段展示，不模拟打字流。

现场操作参考：[证据图谱与流式分析演示](docs/证据图谱与流式分析演示.md)。

模型配置状态不代表连接成功，实际调用成功后报告才标记为真实 AI。分析结果保存到浏览器并包含在报告导出中；失败时保留原有规则报告，不使用模拟文本冒充模型输出。单次请求超时为 60 秒，最多两个并发调用，每分钟最多十次。

AI 请求可能计费；点击按钮会将所列数据和已保存 Markdown 发送给所配置的服务。代码扫描仍未接入。

检查适配器和配置：`node --test scripts/ai.test.mjs scripts/model-config.test.mjs`。适配器测试使用桩响应，实际模型连通性需填写有效配置后验证。

运行演示只需要 Node.js 20 或更高版本，无需安装依赖、Java 或数据库。未配置 AI 时仍可使用样例排查。

## 直接打开

双击 `frontend/index.html` 即可使用。

## 本地 HTTP 访问（可选）

需要通过本地地址访问时，在项目根目录运行：

```sh
npm start
```

访问 http://127.0.0.1:5173 。无需 npm install，仅需 Node.js。端口冲突可用 `PORT=5174 npm start`。


## 工作空间与业务链路

左侧可切换三个工作空间，共九个案例：

| 工作空间 | 业务场景 |
| --- | --- |
| 外卡支付 | 支付成功但通知失败、渠道拒绝、渠道超时 |
| 跨境支付 | 收款人协议过期、银行明细上传失败、海关申报回执待更新 |
| MSO | 外币付款明细待扣款、境外收款人报备锁超时、VA 回调交互记录缺失 |

跨境与 MSO 业务路径依据两个本地仓库的 master 分支静态审阅整理，报告可展开查看文件位置和 commit。交易与日志仍为沙箱数据。各空间的历史、服务配置和业务文档独立保存，原外卡记录保留；本机模型配置共用。详见 [跨境项目扫描与工作空间说明](docs/跨境项目扫描与工作空间说明.md)。

## 可以体验

- 外卡三种场景：支付成功但通知失败、渠道拒绝、渠道超时最终状态未知。
- 按交易号检索内置样例，沿消息 ID 关联 trx 与 daemon。
- 展开日志、上下文与示例代码，查看结论与待确认事项。
- 导出 Markdown 排查单、保存处理反馈、查看历史。
- 服务开关影响排查结果；关闭 daemon 后，通知失败案例变为证据不足。
- 项目知识来源：默认使用 Markdown，支持粘贴或导入文档；可选开启本地项目扫描配置，支持多个仓库路径和分支，默认 master。当前仅保存配置，不读取仓库、不执行扫描，也不改变预设诊断。

记录保存在当前浏览器 localStorage，不同浏览器或地址互不共享。清理站点数据会删除记录；存储不可用或空间不足时明确提示未保存，保留原有记录。

排查记录支持按流水号、商户、问题或结论搜索，按处理状态和 AI 分析状态筛选，并显示当前空间的记录汇总。AI 输出中的有效证据编号（如 `[E1]`）可点击展开对应日志；未匹配的编号只显示文本，不链接到其他证据。

基础诊断使用前端预设规则。点击“AI 分析”后由配置的模型分析问题与证据；该功能不访问真实交易或日志服务器。

Markdown 业务文档点击“保存知识配置”后持久化到当前浏览器 localStorage，页面展示保存时间，刷新后可读取。支持下载当前编辑内容为 `.md` 备份；存储失败会明确提示未保存。后续计划由 Java 后端接入私有 OSS 保存正文，数据库维护文档元信息和版本，详见产品建设方案。

## 文件

- `frontend/index.html`：页面结构。
- `frontend/style.css`：响应式样式。
- `frontend/app.js`：交互与导出。
- `frontend/mock-api.js`：模拟数据层，后续可替换为真实 API。
- `frontend/workspaces.js`：业务空间、跨境案例及代码来源。
- `frontend/investigation.js`：支付状态分析与商户补证。
- `frontend/evidence-graph.js`：证据节点映射、交互图谱与引用高亮。
- `frontend/stream.js`：前后端共享的 SSE / NDJSON 读取器。
- `scripts/serve.mjs`：本地页面服务和 AI 接口。
- `scripts/ai.mjs`、`scripts/model-config.mjs`：模型调用和本机配置保存。
- `scripts/*.test.mjs`：现有功能回归测试。
- `docs/PayTrace演示说明与后续技术架构.md`：产品建设方案与技术架构。

已移除未使用的 Java 草稿、Maven 配置、构建缓存及重复演示数据。后续 Java、数据库和 OSS 接入仅保留设计文档。

运行所有现有测试：`npm test`。
